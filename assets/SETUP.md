# Analytics setup

The GitHub Analytics panels in `README.md` are generated by GitHub Actions in
this repository and committed as static SVGs. There is no third-party render
service in the request path when the profile loads, so the panels do not break
when someone else's Vercel quota runs out.

## One-time repository configuration

1. Push this repository to `github.com/MohammadOmar1054/MohammadOmar1054`.
2. **Settings -> Actions -> General -> Workflow permissions**: select
   **Read and write permissions**, then **Save**.
3. **Actions** tab: run **Metrics** and **Generate Snake** once each via
   *Run workflow*.
4. After **Generate Snake** finishes, uncomment the snake block in `README.md`.

Both workflows then refresh automatically every 12 hours.

## Optional: richer metrics

`metrics.yml` runs with the built-in `GITHUB_TOKEN`, which covers public data.
For private-contribution counts and a few extra plugins, add a classic Personal
Access Token (scopes: `repo`, `read:org`, `read:user`) as a repository secret
named `METRICS_TOKEN`. The workflow uses it automatically when present.

## Why the previous services failed

| Service | Observed status | Cause |
|---------|-----------------|-------|
| `github-readme-stats.vercel.app` | HTTP 503 | shared public instance, permanently rate-limited |
| `github-readme-activity-graph.vercel.app` | HTTP 402 | maintainer's Vercel plan quota exhausted |
| `github-profile-trophy.vercel.app` | HTTP 402 | maintainer's Vercel plan quota exhausted |

HTTP 402/503 responses are server-side; no query-parameter change fixes them.
Self-hosting the render step inside this repo removes the dependency.
